Which flaws in a wearable ECG front-end break arrhythmia detection?

We simulate a cheap analog front-end (AFE), push clean ECG recordings through it, and measure how much a neural-network classifier loses. Then we find the cheapest hardware that stays within 1% of clean accuracy.

The question, and four guesses we will test

Primary: Which AFE non-idealities degrade ECG classification most, and what is the cheapest AFE design that stays within 1% of clean-signal accuracy? Secondary: for a fixed noise budget, is it better to spend on analog hardware or to fix the signal digitally afterward?

H1

Pickup beats bit depth

Electrode impedance mismatch plus finite CMRR (mains pickup) hurts more than ADC bit depth.

H2

High-pass hurts ST classes

A cutoff at or above 0.5 Hz distorts the ST segment, so MI and STTC suffer most.

H3

A cliff, then flat returns

Below some sampling rate and bit depth accuracy collapses. Above it, extra hardware buys almost nothing.

H4

Software rescues cheap hardware

A small digital denoiser recovers most of the loss from a low-cost analog chain.

These are hypotheses to test, not assumptions. If one is wrong, that is a result.

The simulated signal chain

Each block is its own Python module with its own unit test. Every block can be switched off, which is how we isolate one flaw at a time.

Why mismatch plus CMRR matters

Mains hits both electrodes as a common-mode voltage. If the two electrode impedances differ, part of it becomes a differential voltage that the amp cannot reject. CMRR sets how much common-mode survives. That is why the two are modeled together.

Datasheet grounding

Parameter ranges are justified with public datasheets: AD8232, INA333, ADS1292R. No purchase needed.

Realism flags

Any unrealistic assumption gets written down in the paper instead of hidden. Example: ideal electrodes, perfect clock, or noise that is white when real noise is not.

What we sweep

Step one: one-at-a-time sweeps to isolate each flaw. Step two: a fractional factorial or random-search grid to find interactions. Every configuration runs with 3 to 5 random seeds.

Data: all free, all public

Install with pip install wfdb. Cite PTB-XL and PhysioNet exactly as their pages instruct.

Main

PTB-XL

5 diagnostic superclasses: NORM, MI, STTC, CD, HYP (multi-label). Official folds: 1-8 train, 9 validation, 10 test, so no patient leakage. Use 100 Hz or 500 Hz. Start with lead I / II, then go to 12-lead.

Optional

MIT-BIH Arrhythmia DB

Beat-level labels. Used as a second dataset to check that results generalize.

Validation only

MIT-BIH Noise Stress Test

Real recorded baseline wander, muscle artifact, and electrode motion. We use it to check our simulated noise, never to train.

How we measure results

Accuracy

  • Macro AUROC (primary)
  • Macro F1
  • Per-class AUROC, to see which classes suffer
  • Drop vs clean, in percentage points

Cost

  • Rough power proxy: bits × sample rate
  • Simple energy model, with assumptions written down

Statistics

  • Mean ± std across 3-5 seeds
  • Official folds only
  • Same test set for every config

Honesty rules and what could go wrong

Simulated noise might not match real noise

We compare against MIT-BIH NST and report where the match is weak.

Patient leakage

Official PTB-XL folds only. No random re-splitting, ever.

Results might disagree with our hypotheses

Fine. A disproved hypothesis is still a finding. We report all four verdicts.

Someone already did this

We check the literature in weeks 1-2 and do not claim novelty we cannot support.

Compute terms

Check Exea Labs usage terms before heavy MI300X runs. No hardware purchases.
